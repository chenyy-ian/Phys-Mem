stage 5
本阶段解决的科学问题：
LightGlue 只看语义匹配置信度时，可能把“语义上匹配但空间漂移很大”的帧误认为稳定记忆。Spatial Penalty 引入匹配点位移，尝试区分 semantic consistency 和 spatial consistency。
核心假设：
稳定 memory 不仅需要高语义匹配，还需要匹配点的 2D 位移处于合理范围。平均位移越大，越可能对应 ghosting、texture drift、错误旧场景残留或大视角不适配。
局限性：
这个 penalty 仍是 2D 图像平面约束。真实相机运动、前进运动、尺度变化、透视变化会天然产生大位移，可能被误罚。它也不知道位移来自合理 3D 视差、物体运动，还是生成漂移。
Reviewer 问为什么还需要 Depth：
因为 2D displacement 不能区分“物理合理的大位移”和“生成错误导致的漂移”。Depth/3D 几何可以把像素运动解释为相机运动、视差、遮挡和场景结构变化，从而把 flat image matching 提升到 physical consistency。
消融实验设计
Alpha sweep：
固定 seed/action/scene，比较 alpha=0, 0.0005, 0.001, 0.002, 0.005。指标看 ghosting、texture drift、memory replacement、VBench-Long temporal/background consistency。

Semantic vs Spatial：
同一 LightGlue 匹配结果下比较：
semantic_similarity 决策 vs final_similarity 决策。验证 Spatial Penalty 是否减少旧纹理残留、重复纹理误保留和 scene ghosting。

场景分组实验：
低运动静态场景、重复纹理场景、大尺度前进场景、大视角转向场景分别统计。预期 penalty 在重复纹理/ghosting 上提升，在大尺度真实运动中可能失败。

这一步最适合作为 LightGlue 到 Depth 的中间阶段：它证明“仅语义匹配不够，需要空间一致性”，同时也暴露“仅 2D 空间一致性不够，需要 3D/Depth 解释”。

stage 6
本阶段解决的问题是：ORB 和 LightGlue 只能回答“图像是否相似”或“语义匹配是否可靠”，但 Memory 真正需要判断的是“物理世界状态是否仍然一致”。Depth 引入的是几何证据：同一记忆是否还能解释当前场景的空间结构。
核心假设
如果 reference frame 和 current/middle frame 属于同一个稳定物理世界，那么它们的相对 depth structure 应该保持连续或可比较；如果 depth difference 明显增大，说明旧 memory 可能已经不再是可靠物理锚点。
局限性
DepthAnythingV2 是单目 depth，通常只有相对深度，没有真实尺度；它也没有相机位姿、运动方向和动作意图。因此 depth difference 可能把“合理前进导致的深度变化”误判成世界变化，也可能在原地转头时失效。
为什么 Depth 无法解决原地转头？
原地转头时，世界没有物理位置平移，但视野内容大幅变化。单帧 depth map 只描述当前可见区域的相对深度，不知道相机 yaw 变化，也不知道新出现区域与旧区域在同一个 3D 世界中的关系。没有 Action/pose，Depth 无法判断这是“合理转头”还是“场景漂移”。所以 Depth 不能回答原地转头问题。
为什么还需要 Action？
Action 提供因果解释：前进、转向、抬头、低头会导致不同的合法几何变化。Depth 只能看到结果，Action 能解释变化是否合理。下一阶段应该让 Memory Decision 使用 action-conditioned physical consistency，而不是只看 depth map 差异。

stage 7
Stage7 解决的是：Depth 能感知几何世界，但不能感知玩家意图。玩家原地快速转头时，Depth 可能变化很小，甚至局部深度分布稳定，但视频记忆仍然应该“翻页”，否则旧视角 KV 会继续污染新视角生成，出现拖影、残影和方向性纹理漂移。
核心假设是：玩家输入是未来视角变化的因果先验。Mouse rotation 和 keyboard movement 虽然不是图像相似度，但能提前说明“世界观察方式即将改变”。
局限性
Action 不是物理观测，只是意图信号。玩家按 W 不代表真的前进，可能撞墙、被场景阻挡，或者生成模型没有正确响应；鼠标转动也不告诉我们新视角里具体出现什么。因此 Action 不能替代 Depth。
Depth 也不能替代 Action。Depth 描述的是已经看到的几何状态，不知道玩家下一步要做什么；原地转头、快速扫视、突然回头这类动作，Depth-only 容易低估记忆更新需求。
所以二者是互补关系：Depth 判断“世界几何是否变了”，Action 判断“玩家是否正在要求视角/运动状态改变”。
Reviewer 问法
如果 Reviewer 问“为什么有 Action 还需要 Depth”，理论回答是：Action 是 cause，不是 observation。它能预测运动意图，但不能验证物理结果。Depth 是 physical evidence，能判断场景结构是否真的发生了几何变化。没有 Depth，系统会把所有强输入都当作世界变化，容易过度替换 Memory。
如果 Reviewer 问“为什么 Depth 后还需要 Action”，理论回答是：Depth 是 state measurement，不包含 agent intent。原地转头、视角快速变化、短时间输入突变时，Depth 差异可能滞后或不明显，但 Memory 已经需要更新。因此 Action 提供了 Depth 缺失的主动控制信息。
建议消融实验
Depth-only vs Action Timeline 分析
场景：玩家发呆、慢走、快跑、原地转头、左右平移。
观察：Depth similarity、rotation_speed、movement_speed、后续拖影。
预期：原地转头中 Depth 变化弱，但 Action rotation 强。

去掉 Mouse cue
只保留 keyboard movement。
观察原地转头和快速扫视。
预期：turn 类 intent recall 明显下降，证明 mouse rotation 是独立贡献。

去掉 Keyboard cue
只保留 mouse rotation。
观察慢走、快跑、左右平移。
预期：movement intent 区分能力下降，尤其 Walk / Run / Left / Right。

Action threshold sweep
扫描 rotation / movement threshold，统计 action trigger、误触发、漏触发。
目标是证明 Action cue 需要 calibration，不能直接替代 Fusion 或 Depth。
